# neb-storage

Synchronous, read-only Local / WebDAV / S3 adapters for the command service. The first alpha supports browse, streaming download and safe local publication. Remote upload, bidirectional synchronization and background credential storage are intentionally unavailable; the UI must say so.

`StorageRegistry::open(data_dir)` loads sanitized source settings. `add(AddStorageRequest)` adds or reconnects a location; identical kind/endpoint/root/bucket preserves its ID. Secrets are held only in the registry's process memory, are not `Debug`/`Serialize`, and never enter the config. Restart marks remote locations disconnected until supplied again. `browse(id,prefix,limit,cursor)` returns immediate children, up to 1,000 per page. S3 uses native ListObjectsV2 continuation tokens; WebDAV and local cursors are sorted last keys. WebDAV servers still return a full depth-one response and are bounded at 16 MiB.

For separate CLI invocations, credentials can be supplied through source-specific environment variables at registry startup. The prefix is `NEBULUME_STORAGE_<UPPERCASE_ID_WITH_HYPHENS_REPLACED_BY_UNDERSCORES>_`. S3 reads `ACCESS_KEY`, `SECRET_KEY`, optional `SESSION_TOKEN`; WebDAV reads `USERNAME`, optional `PASSWORD`, or `ANONYMOUS=1` for public sources. Environment values are never persisted. Only complete S3 credentials or an explicit WebDAV selection mark the saved source connected. A long-running CLI stdio session can instead retain credentials in memory.

`reader(id,key)` streams; `fetch(id,key,destination)` pins the selected parent directory, writes to a random sibling temporary file, flushes, verifies complete SHA-256 by reading the temporary file again, and atomically publishes by creating a hard link without replacement. It then verifies the published file too. Original remote objects are never altered. Transfers have a 15-second connection and 300-second request timeout in this alpha; large transfers that exceed that timeout fail and can be retried.

Storage keys reject absolute paths, traversal, Windows drive syntax, separators, reserved names and control characters. Existing symlinks/reparse points are rejected; local opens are additionally capability-relative. HTTP redirects are disabled to avoid forwarding credentials across origins. HTTPS is required except loopback test endpoints. WebDAV response paths must remain within the configured origin/root. S3 uses SigV4 path-style requests, explicit credentials and region (default `us-east-1`); ETags are not treated as SHA-256. S3 session tokens are supported by the library input.

`PreparedDestination` retains an existing ancestor handle while the user reviews an import. `ScopedDestination` creates and opens each child directory with no symlink following and performs temporary creation, verification, hard-link publication and cleanup through fixed directory capabilities. Replacing a directory pathname during a copy cannot redirect publication to the replacement. Destinations must support hard links: FAT/exFAT destinations fail explicitly and safely, with no unsafe fallback. FAT/exFAT source cards can be read normally. Remote endpoint compatibility still needs real service CI or explicitly provisioned test services. Offline tests use only temporary files and loopback HTTP, never live accounts.

Reference APIs: [reqwest 0.12](https://docs.rs/reqwest/0.12/reqwest/), [S3 Signature Version 4](https://docs.aws.amazon.com/AmazonS3/latest/API/sig-v4-authenticating-requests.html), [WebDAV RFC 4918](https://www.rfc-editor.org/rfc/rfc4918).
