# Nebulume 设计系统与全应用重建

日期：2026-11-10
状态：已确认（2026-11-10）
视觉基准：`docs/mockups/design-system.html`（2026-11-10 已认可）

## 为什么做

暗房重设计（PR #4）只换了颜色、加了视图，没有统一规则：

- 每个页面自己写按钮、卡片和间距。导入页上的按钮有 32、36、64px 三种高度，圆角有五种。
- 同一件事有多个入口。比如图片库页头的“选片”标签和“选图”按钮重复，“详情”按钮和信息面板重复。
- 导入页同时用了编号卡片、箭头、页头步骤条和右侧历史栏四种表达进度的方式。在 1440×900 下，底部操作栏会盖住“怎么整理”。
- 查看器还是“固定工具栏 + 信息面板”。用户想要的是能自己决定看到什么，并且以后能加新功能。

目标是先有一套设计系统，再用它重建整个应用（图片库、选片、概览、查看器、导入、位置、设置、对话框）。页面之间的差别只来自内容，不来自各自的样式。

## 目标

1. 一套 token（颜色、字号、间距、圆角、控件高度、动效），取值以 `design-system.html` 为准，深浅两套。
2. 一组共享 Solid 组件。页面里所有可交互控件都由它们构成，不再各自写控件样式。
3. 两种页面版式（单栏、主栏 + 侧栏），所有页面套用同一骨架。
4. 按上述系统重建全部页面，并删除旧的分页面 CSS（`styles.css`、`import.css`、`cache-settings.css`、`inspector.css`、`viewer.css`、`culling.css` 等），不在旧样式上叠加覆盖。
5. 查看器的四角叠加信息与信息面板字段固定，都可自定义；叠加部件采用可注册的形式，方便以后加新部件。
6. 一个开发版内的组件参考页，加一个自动检查脚本，让样式漂移在提交前就能被发现。

## 不做

- 后端与 Rust 代码不改；所有命令与数据格式保持不变。
- 不加新的业务功能。叠加信息与字段固定是本次唯一的新能力。
- 推迟到以后：⌘K 命令面板、时间轴拖动条、幻灯片、对比视图扩展、“在访达中显示”、“复制原片到…”。
- 偏好仍存 `localStorage`，不迁到 Rust。

## 反目标（做到了也算失败）

- 某个页面为“好看一点”单独写颜色、阴影、圆角或控件高度。
- 同一操作出现两个同权重入口。
- 为了改版删掉现有能力。下文“必须保留的能力”中的每一项都要能在新界面找到。
- 出现阴影、渐变、模糊、发光、小于 11px 的字，或 400/500 以外的字重。
- 照片周围出现彩色界面元素。状态色只用于留用、淘汰、警告、错误和星级。

## 约束

- SolidJS + Vite，Tauri 2 桌面应用，同时有浏览器演示模式。
- 桌面版离线可用：图标与字体不能依赖 CDN。
- 窗口最小 960×600（主窗口）与 640×480（查看窗口）；1024 宽以下侧栏收起为抽屉（沿用现有逻辑）。
- 无障碍：沿用现有焦点管理、roving tabindex、对话框焦点陷阱与 `aria-*`。所有纯图标按钮都要有可访问名称与悬停提示。
- 减少动态效果偏好下所有动画即时完成。
- 现有 97 个单元测试与 111 个浏览器测试覆盖的行为都要保留。测试可以改选择器，不可以删掉对行为的断言。

## 设计系统（已决定）

### Token

取值与 `design-system.html` 的 `:root` 和 `[data-theme="light"]` 完全一致。CSS 变量沿用 `--nl-` 前缀，语义名如下：

| 类别 | 变量 |
| --- | --- |
| 表面 | `--nl-stage` `--nl-rail` `--nl-side` `--nl-canvas` `--nl-raised` `--nl-hover` `--nl-pressed` `--nl-line` `--nl-line-strong` `--nl-overlay` `--nl-scrim` |
| 文字 | `--nl-text` `--nl-text-2` `--nl-text-3` `--nl-inverse` |
| 操作 | `--nl-primary` `--nl-primary-hover` `--nl-ring` |
| 状态 | `--nl-pick` `--nl-reject` `--nl-warn` `--nl-info` `--nl-star` `--nl-series`，以及 `--nl-tint-{pick,reject,warn,info}` |
| 字号 | `--nl-t-11` `-12` `-13` `-14` `-16` `-18` `-22` |
| 间距 | `--nl-s-1`…`--nl-s-10`（4、8、12、16、20、24、32、40） |
| 圆角 | `--nl-r-thumb`(2) `--nl-r-xs`(4) `--nl-r-sm`(6) `--nl-r-md`(8) `--nl-r-lg`(12) `--nl-r-pill` |
| 控件高度 | `--nl-h-xs`(24) `--nl-h-sm`(28) `--nl-h-md`(32) `--nl-h-lg`(40) |
| 动效 | `--nl-ease` `--nl-d-fast`(120ms) `--nl-d-base`(180ms) `--nl-d-slow`(280ms) |

- 查看器舞台在两种主题下都是深色。查看器内部的文字、按钮与叠加部件使用一组固定的深色值（与深色主题相同），不随主题变化。
- 字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Segoe UI", "Microsoft YaHei", sans-serif`；等宽：`ui-monospace, "SF Mono", Menlo, Consolas, monospace`。这是我的决定：demo 中的 "Anthropic Sans" 不随应用分发，不写入应用。
- 数字统一 `font-variant-numeric: tabular-nums`。

### 图标

改用 Tabler 线性图标（MIT），与 demo 一致，打包进应用，不走 CDN。现有 `Icon.tsx` 保留调用方式 `<Icon name="…" />`，内部换成 Tabler 的 SVG 路径，只收录用到的图标。用哪个包或怎么引入由实现者决定（如 `@tabler/icons-solidjs`，或从 `@tabler/icons` 复制所需 SVG），版本要锁定。尺寸：正文内 16px，图标按钮 18px（md）/16px（sm）/14px（xs），图标栏 20px。

### 组件

组件放在 `packages/ui/src/ui/`，每个组件一个 `.tsx` 加同名 `.css`。只有这些文件和 `tokens.css` 可以写颜色、圆角、控件高度与字号。

| 组件 | 变体与要点 |
| --- | --- |
| `Button` | `primary` `secondary` `ghost` `danger`；尺寸 `sm`(28) `md`(32) `lg`(40)；可带左侧图标；`busy` 时显示小转圈并禁用 |
| `IconButton` | 尺寸 `xs`/`sm`/`md`；必须有 `label`（同时用作 `aria-label` 与悬停提示），可带快捷键提示；`pressed` 状态 |
| `Tooltip` | 悬停或聚焦 500ms 后出现，可显示快捷键 `Kbd` |
| `Kbd` | 快捷键徽标 |
| `Field` | 标签在上，说明或错误在下，`for`/`id` 自动关联 |
| `TextInput` | 可带前置图标、后缀（单位）、快捷键提示；`invalid`；`sm`/`md` |
| `Select` | 原生 `<select>` 外加统一外观，`sm`/`md` |
| `Segmented` | 用于视图切换和单选组，`role="tablist"` 或 `radiogroup`；`sm`/`md` |
| `Switch` `Checkbox` `Radio` | 外观见 demo |
| `Slider` | 缩略图大小等 |
| `Chip` | 可移除的筛选标签，24px |
| `Toggle` | 胶囊形开关按钮（如“隐藏淘汰”），24px |
| `Badge` | 中性 / `pick` / `reject` / `warn` / `info`，20px |
| `StatusDot` | `ok` `off` `warn` `bad`，总与文字同时出现 |
| `Group` + `ListRow` | 分组标题（14/500，右侧可放计数或一个控件）加一组行。行的左边是名称与一句说明，右边是一个控件；`nav` 变体整行可点并带右箭头；可带前置图标块 |
| `Menu` | 沿用 `ContextMenu` / `OverflowMenu` 的键盘逻辑，统一外观；支持分组标题、分隔线、快捷键、危险项 |
| `Toast` | 底部居中，6 秒消失，带撤销的 10 秒；错误提示保持到关闭；同时最多显示一条，新的替换旧的 |
| `Banner` | 中性 / `info` / `warn` / `error`；放在内容区顶部，持续到处理或关闭 |
| `Dialog` | 沿用 `Modal` 的焦点陷阱；页头标题加关闭按钮，正文，底部右对齐的按钮（最多一个主按钮或危险按钮） |
| `Steps` | 多步流程唯一的进度表达，放在页头 |
| `Progress` `Spinner` | 进度条 4px；转圈 16px |
| `EmptyState` | 图标块、标题、一句说明、最多两个按钮 |
| `DataTable` | 表头 12px 次要色，数字右对齐 |
| `PageHeader` | 56px：标题（加可选的次要说明），中间放视图切换或 `Steps`，右侧最多一个主或次按钮，再加“更多” |
| `Toolbar` | 44px：搜索、筛选、标签、排序、视图开关 |
| `SinglePage` `SplitPage` | 单栏（内容最宽 760px，居中）；主栏 + 300px 侧栏，侧栏底部可固定主操作 |

### 规则

- 一处最多一个主按钮（`primary`）。页头的主操作多数情况下用 `secondary`，只在页面就是为了完成这件事时（如导入的“核对导入计划”“开始导入”）用 `primary`。
- 同一操作只有一个可见入口，另加键盘快捷键和右键菜单不算重复。
- 设置类选项一律用 `Group` + `ListRow`，不用孤立的表单卡片。
- 状态色不单独表达含义，总与图标或文字同时出现。
- 句首大写，句中不加粗；文件名和路径可用等宽字体。
- 内边距：页头与工具栏左右 20px，内容区 24px；分组之间 24px；行内控件间距 8px。

### 防漂移

- 开发版加组件参考页：`?design=1`，渲染所有组件的全部变体（深浅主题切换），内容与 `design-system.html` 对应。生产构建不包含。
- 一个检查脚本（`pnpm check:design`，并入 `pnpm test`），检查范围是 `src/ui/` 与 `tokens.css` 以外的 CSS 文件：
  - 不允许十六进制或 `rgb()` 颜色；
  - 不允许 `box-shadow`，用 `inset` 描边或焦点环的除外；
  - 不允许 `font-weight` 取 400、500 以外的值；
  - 不允许 `font-size` 小于 11px，也不允许直接写像素字号，只能用 token；
  - 不允许 `linear-gradient`、`radial-gradient` 和 `filter: blur`。
  检查时跳过照片本身用到的颜色（直方图 RGB 通道）。这些颜色集中写在 `tokens.css` 的 `--nl-hist-*` 中。

## 应用骨架

- 图标栏 56px：图片库、导入、位置；底部是“打开文件…”和设置。内部分区 id 不变（导入仍是 `cards`），只调整显示顺序。
- 侧栏 220px，只在图片库里出现：图库列表与文件夹树（沿用 `LibrarySidebar` 的行为）。
- 其余页面：`PageHeader`，下面是可选的 `Toolbar`，再下面是 `SinglePage` 或 `SplitPage`。

## 各页面

### 图片库

- 不再有“全部图片库”卡片页（我的理解，来自用户 2026-11-10 的回答）。点图标栏的“图片库”直接打开上次打开的图片库；没有记录时打开侧栏里的第一个。
- 一个图片库都没有时，内容区显示 `EmptyState`：“还没有图片库”，主按钮“新建图片库”（打开 `LibraryDialog`），次按钮“从存储卡导入”。浏览器演示模式下主按钮为“选择照片”。
- 原卡片页上的能力全部移到侧栏：侧栏标题旁的“+”新建图片库；每个图片库行的“⋯”菜单包含编辑、扫描、预生成缩略图、拍摄时间补索引、内容指纹、移除登记；在线状态用行尾的 `StatusDot` 表示，悬停显示状态文字与原因。
- 页头：库名，次要说明为张数（选中文件夹时显示路径）；中间是 `Segmented`：照片 / 选片 / 概览；右侧是“扫描更新”（`secondary`）和“更多”（图库设置、移除登记、导出留用等现有菜单项）。现有的“选图”和“详情”按钮去掉。
- 工具栏：搜索框（显示 `⌘F` 提示，保留现有 ⌘F 聚焦）、“筛选”`ghost` 按钮、当前筛选的 `Chip`、空白、“隐藏淘汰”`Toggle`、排序 `Select` 与升降按钮、缩略图大小 `Slider`、详情 `IconButton`（I）。
- “筛选”展开第二行工具栏，放评级、旗标、格式、机身、镜头、拍摄日期（与现在相同，记住展开状态）。生效的筛选显示为可移除的标签。
- 选中多张时，工具栏换成批量操作条：已选数量、星级、留用 / 淘汰 / 清除、导出、移到废纸篓、取消选择。
- 照片墙、日期标题、悬停信息沿用现有布局，改用 token。
- 状态栏（已载入数量、同步错误）改为工具栏右侧的计数文字加 `Toast` / `Banner`，不再单独占一条底栏。
- 详情面板（I）就是信息面板组件（见查看器），在右侧 300px。
- 空状态与“没有找到照片”使用 `EmptyState`。

### 选片与完成选片、概览

- 沿用 PR #4 的结构与行为，样式全部改用组件和 token。CullPanel 用 `Group` 的样式，留用 / 淘汰按钮是 `Button secondary`，选中时用状态色描边。完成选片的两栏用 `SplitPage` 的样式，危险操作用 `Button danger`。
- 选片时原有的底部 HUD（星级、旗标、序号）取消。侧面板始终显示当前照片的星级、旗标和“序号 / 总数”，打标确认的 250ms 动效在侧面板上播放；叠加部件里有这些字段时也同步播放。这样即使用户从叠加布局里移除了这些部件，反馈也不会丢（我的决定）。
- 选片模式下原来的 Tab（显示或隐藏 HUD）改为与 D 相同：显示或隐藏叠加信息（我的决定）。快捷键表与设置里的快捷键页同步更新。
- 概览的图表沿用单系列色 `--nl-series`，数字用 22/500。

### 查看器

顶栏 48px，浮在照片上：返回、文件名（后跟文件夹与“序号 / 总数”）、空白、查看 / 选片 `Segmented sm`、叠加信息开关（D）、对焦点（P，选片模式下为 Shift+F）、信息（I）、裁剪（C）、更多。“更多”收纳导出、重新读取原图、全屏（F）、复制路径、在图片库中显示、加入图片库、编辑叠加信息…、移到废纸篓。独立窗口另有关闭按钮。

- 约 2 秒无操作后，顶栏、前后箭头和缩放控件淡出；鼠标移动或键盘操作后再出现。
- 四角叠加信息默认不随工具栏淡出，按 D 显示或隐藏。设置里有一项“叠加信息随工具栏淡出”，默认关闭。这是我的决定，与 demo 说明里“四角信息约 2 秒淡出”不同，因为用户要的是像相机 DISP 一样连看时一直可见。
- 缩放、平移、双击 100%、滚轮或捏合以光标为中心，沿用现有实现。

#### 叠加部件

- 四个角 `tl` `tr` `bl` `br` 各是一摞部件，从上往下排（底部两角从下往上贴边）。每角数量不限，宽度不超过画面的 44%。
- 部件注册表 `viewer-widgets.ts`：每个部件有 `id`、名称、分组、`render(asset, context)`，以及依赖（如是否需要直方图）。叠加层只按布局渲染注册表里的部件。以后的新功能（如峰值对焦、地图）注册新部件即可。
- 首批部件：
  - 文件名、序号、文件夹
  - 拍摄时间
  - 星级、旗标
  - 曝光组合（光圈、快门、ISO、焦段），以及光圈、快门、ISO、焦段各自单独的部件
  - 曝光补偿、测光模式、白平衡
  - 机身、镜头、机身与镜头
  - 直方图（RGB，140×44）
  - 尺寸、文件大小、格式
  - GPS
- 缺少数据的部件不显示，不留空位。直方图复用 `asset.histogram`（服务端已缓存），只在显示该部件时请求。
- 默认布局（与 demo 相同）：左上拍摄时间；右上星级、旗标；左下机身与镜头、曝光组合；右下直方图。
- 编辑模式（“更多 → 编辑叠加信息…”，或在叠加部件上右键）：
  - 照片变暗，每个角末尾出现“+ 添加”，底部出现备选部件托盘和“完成”。
  - 可以从托盘拖进任意角，也可以在角之间或角内拖动排序，拖回托盘即移除。
  - 键盘替代：每个部件和每个“+ 添加”都可聚焦。“+ 添加”打开部件菜单；部件的菜单提供上移、下移、移到其他角和移除。
  - 底部托盘里有“恢复默认”。
- 布局存 `localStorage` 的 `nebulume.viewer.overlay`，所有查看器（主窗口内与独立窗口）共用一份。查看和选片两种模式共用一份布局。

#### 信息面板

- 主窗口查看器、独立窗口和图片库详情共用同一个组件（取代现有 `AssetInspector` 的布局，保留其全部内容：直方图与来源说明、曝光三要素、文件信息、离线缓存、对焦状态、解码诊断、裁剪编辑、导出、重新读取）。
- 自上而下：直方图，固定字段（可拖动排序，每行右侧图钉可取消固定），“全部 EXIF”（折叠，点图钉固定），文件与缓存，诊断（折叠）。
- 默认固定：曝光（光圈 · 快门 · ISO）、焦距、镜头、机身、拍摄时间、尺寸。
- 固定的字段与顺序存 `nebulume.inspector.pinned`，各处共用。
- 键盘：行可聚焦，Alt+↑/↓ 移动顺序，回车切换固定。

### 导入

页面骨架：`PageHeader`，标题“导入”，中间是 `Steps`（设置 / 核对 / 完成），右侧是“历史”`ghost` 按钮。下面是 `SplitPage`。

**第 1 步：设置**

- 主栏三个 `Group`，自上而下：
  1. 从哪里导入。检测到的存储卡与外接盘显示为来源卡片（名称、类型、容量；已登记的卡显示卡名）。分组标题右侧是“选择其他文件夹…”和“刷新”。“所有卷”开关放进刷新按钮旁的菜单。手填路径的输入框保留，放在“选择其他文件夹…”之后。
          - 选中未登记的卡时，卡片下方出现一个 `ListRow` 组：卡名称（输入框）与“登记这张卡”，或者“绑定到已登记的卡”（下拉）。写明可以不登记直接导入。
     - 选中已登记的卡时，卡片下方的 `ListRow` 组可改卡名；“怎么整理”的方案菜单里有“设为这张卡的默认方案”。卡的设置只在这里，设置页“其他配置”表格继续指向导入（我的决定）。
  2. 导入到。行：目标图片库（`Select`，右侧显示来源类型与在线状态）；跳过图片库里已有的照片（`Switch`，说明“按内容判断，同名不同内容会另存”）；远端目标需要写入测试时，在这一组里显示状态与“测试写入”。
  3. 怎么整理。分组标题右侧是导入方案 `Select`（手动设置，或已保存的方案；末尾一项“另存为方案…”打开 `Dialog`）。行：分类依据（`Segmented`：拍摄日期 / 导入日期 / 保留卡内目录 / 不分日期）；日期层级（`Select`）；没有拍摄时间时（`Select`：放进 unknown-date / 用文件修改日）；子目录（`TextInput`，可选）；按类型分开（`Switch`，说明“RAW / JPG / TIFF / OTHER，XMP 跟随 RAW”）；疑似重复也导入（`Switch`，只对远端目标显示）。
- 侧栏“将会导入”：来源、目标图片库、整理规则的一句话概括，以及按当前规则生成的目录示例（文件夹树，等宽字体）。底部固定主按钮“核对导入计划”（`primary lg`，铺满侧栏宽），下方一行说明“下一步逐项列出，确认后才开始复制”。
- 精确的新照片数、跳过数和占用要读取来源，只在第 2 步显示；第 1 步不显示估计数字。这是根据 `import.plan` 的现有成本做的决定，与 demo 中第 1 步就显示“412 张”不同。

**第 2 步：核对**

- 主栏：工具栏（按状态筛选的 `Segmented`：全部 / 新 / 已存在 / 疑似重复 / 问题），下面是 `DataTable`（文件、去向、状态 `Badge`、大小），沿用现有的分页与行为。
- 侧栏：数量汇总（新照片、跳过、疑似重复、占用、目标可用空间）；有问题时显示 `Banner warn`。底部是“开始导入”（`primary lg`）与“返回修改”（`ghost`）。
- 复制中：侧栏换成不确定进度条与一行状态文字（“正在复制并校验…”），主按钮变为不可用。`import.execute` 是一次阻塞调用，没有进度事件，后端不改，所以不显示当前文件和剩余时间（我的决定）。

**第 3 步：完成**

- 主栏：`EmptyState` 式结果（成功或部分失败的图标、标题、一句说明），失败项用 `DataTable` 列出。
- 侧栏：本次导入汇总；“打开图片库”（`primary`），“再导入一批”（`secondary`）。

**历史**

页头的“历史”打开右侧 360px 抽屉，列出导入记录（状态点、来源、目标、时间、数量），点开一条看详情与失败原因，可跳到该批次照片（现有 `import_batch_id` 筛选）。

### 位置

- `PageHeader`：“位置”，右侧“添加网络位置”（`secondary`）。
- `SinglePage`：`Group`“网络位置”，每个连接是一行 `ListRow nav`（图标块、名称、地址、`StatusDot` 加状态文字，右箭头）。点进去后是同一页内的详情视图（返回按钮、连接信息、凭据状态、证书信任、目录浏览、“用这个目录建图片库”），沿用现有功能。
- 不列出存储卡。卡的改名与默认方案留在导入页（我的决定，见下）。
- 空状态用 `EmptyState`。
- 浏览器演示的限制提示用 `Banner info`。

### 设置

- `PageHeader`“设置”，中间 `Segmented`：外观与浏览 / 缓存与离线 / 快捷键 / 其他配置 / 关于。保留现有的五个分区，原来的左侧二级导航去掉。这是我的决定，demo 里只画了四个分区。
- `SinglePage`，每个分区由若干 `Group` 组成。缓存的用量用 `Progress` 加数字，位置迁移等流程沿用现有逻辑。快捷键用 `DataTable`。“关于”含版本、更新（`UpdatePanel` 的内容）与诊断。
- 破坏性操作（清理缓存等）放在所在分区的最后一组，用 `Button danger sm`，确认走 `Dialog`。

### 对话框

`LibraryDialog`（新建、编辑图片库）、`StorageDialog`（网络位置）、`ConfirmDialog`、TLS 证书确认、移除图片库、内容指纹、拍摄时间补索引：全部改用 `Dialog`，表单用 `Field` 和 `Group`。

## 必须保留的能力
