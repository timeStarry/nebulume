# UI/UX 研发与验收标准工作流

本文规定界面功能从开工到合并的节奏和验收口径。规则本身见 `AGENTS.md` 的「UI & UX 工程治理铁律」，Token 与原语见 `packages/ui/README.md`，视觉决策见 `docs/superpowers/specs/2026-11-10-design-system-design.md`，交互细节见 `docs/INTERACTION.md`。几处冲突时，以 `AGENTS.md` 为准，并在同一个 PR 中修正其他文档。

## 1. 三层落位

开工前先确定每段代码属于哪一层，在 PR 描述中列出。

| 层 | 位置 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 状态与契约 | 纯 TS 模块（`model.ts`、`culling.ts`、`management-sync.ts`、`concurrency.ts`…）、`api.ts` 命令、Tauri 跨窗口事件 | 选择、队列、撤销栈、乐观更新与回滚、同步对账；有单元测试 | import 组件或 CSS；读 DOM 尺寸 |
| Token 与原语 | `src/tokens.css`、`src/ui/` | 定义颜色、圆角、高度、字号、毛玻璃、动效；无业务含义的组件 | 引用图库、资产等业务类型 |
| 薄视图 | 页面与功能组件及其 CSS | 把状态接到原语上，布局与文案 | 写色值、阴影、模糊、px 字号；持有可测试的业务规则 |

新增业务规则先写在状态层并补单元测试，视图只调用。原语缺失时先在 `src/ui/` 补原语（附 `?design=1` 参考页变体），再在页面使用。

## 2. 两段式开发纪律

每个界面功能分两个阶段，可以是两个 PR，也可以是同一 PR 的两组提交，但第二阶段不能在第一阶段验收前开始。

### 阶段一：白盒交互与性能（Wireframe & State）

只用现有原语和中性表面，不做材质、毛玻璃和动效。交付物：

1. 状态模型与单元测试：正常路径、失败回滚、撤销、迟到响应（请求版本或 `ConcurrencyGate`）。
2. 跨窗口契约：主窗口与查看窗口各自操作后另一侧结果一致；窗口重新聚焦不重复请求；同步失败可见并可重试。浏览器测试用 IPC fixture 断言事件与命令顺序。
3. 键盘路径：功能全部操作不碰鼠标即可完成；快捷键登记在集中定义处并出现在设置页「快捷键」。
4. 性能：用 1 万张样本库（demo 模式生成或真实库）验证：
   - 快速拖动滚动条时挂载的缩略图节点数随视口变化，不随库大小线性增长；
   - DevTools Performance 录制滚动 5 秒，无超过 50ms 的长任务，无连续掉帧；
   - 预览请求同时不超过调度上限，滑过的项被撤销或降级。
5. 视口：最小窗口 960×600 与 1440×900 下没有窗口级滚动条，没有嵌套双滚动条。

阶段一验收结论（数据、录屏或截图）写入 PR 描述，评审确认后进入阶段二。

### 阶段二：材质与微动效精修（Polish Pass）

只改表现，不改状态模型与命令。允许：

- 浮动层使用 `--nl-glass` + `--nl-glass-blur`（只能在 `src/ui/` 原语里写 `backdrop-filter`），浮起层加顶部 `--nl-highlight` 受光边；
- 在分段控制器、浮动操作坞、单张悬停与局部状态切换上用 `--nl-spring`，只动 `transform` / `opacity`；
- 渐进加载的淡入、HUD 胶囊、Undo Toast 的进出。

阶段二提交后重新跑阶段一的性能录制，滚动指标不得退化；同时截取深浅两种主题、1440×900 与 1024×700 四张截图附在 PR。

## 3. 标准交互契约

### 渐进加载

骨架格（`--nl-skeleton`，静态无闪光）→ 已缓存的缩略图放大占位 → 高清预览就绪后淡入（`--nl-d-base`）。切换图片时保留上一张或占位直到新图解码完成；失败显示明确状态，不留白框。

### 乐观交互与撤销

| 操作 | 交互 |
| --- | --- |
| 评级、旗标、色标 | 立即生效，写入失败回滚并提示；`Ctrl/⌘+Z` 逐步撤销；键盘触发时显示 HUD |
| 移到废纸篓、批量淘汰 | 不弹确认；立即从网格移除并把焦点移到下一张；`toasts.show({ action: 撤销 })` 保留 10 秒，`Ctrl/⌘+Z` 等价 |
| 移除图片库、重新绑定目录、清空缓存、完成选片后批量删除 | 影响超出当前选择或不可逆，使用 `Dialog` 确认并写明影响范围 |

撤销必须复原到操作前的状态：文件位置、评级、旗标、选择和焦点照片。

### 键盘与 HUD

- 每个高频按钮的 Tooltip 显示 `<Kbd>`；纯图标按钮必须有 `label`。
- 键盘打星、留用、淘汰、撤销时，视口底部居中显示毛玻璃 HUD 胶囊（如「★★★ 3」「留用」「已撤销」），存在 `--nl-d-hud`，下一次按键立即替换，`role="status"`、`aria-live="polite"`，不抢焦点。
- 输入框获得焦点时暂停全局单键快捷键。

### 排版

- 数字、EXIF、文件大小、计数、序号：`tabular-nums`（`body` 已默认设置，组件不得覆盖为 `proportional-nums`）。
- 单行标签：`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`，并以 `title` 或 Tooltip 提供全文。
- 多行说明 `text-wrap: pretty`，标题 `text-wrap: balance`；容器加 `min-width: 0` 防止 flex/grid 子项撑破。
- 文件名、路径、EXIF 原值、错误详情显式 `user-select: text`，其余界面 `user-select: none`。

## 5. 自动化路线

当前机器门禁只覆盖 CSS 静态规则（`scripts/check-design.mjs`）。以下检查计划补到 Playwright（`tests/browser/`），补齐后从人工项改为自动项：

1. 视口：每个工作区在 960×600 下断言 `document.scrollingElement.scrollHeight <= innerHeight`，且同一路径上的祖先不同时可滚动。
2. 右键：在非输入区派发 `contextmenu`，断言事件被 `preventDefault`。
3. 选中：断言网格、工具栏 `getComputedStyle(el).userSelect === 'none'`，路径与 EXIF 值为 `text`。
4. 网格规模：注入 1 万张 fixture，滚动到底，断言 `.thumbnail` 节点数小于固定上限。
5. 撤销：对每个可逆命令执行「操作 → 撤销」，断言状态与操作前一致且出现带「撤销」按钮的 toast。
6. 快捷键：遍历集中定义的键位表，断言每个 Tooltip 含对应 `<kbd>`。
