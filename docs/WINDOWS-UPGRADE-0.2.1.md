## 物理安装与原生影像

0.2.1 已通过正式 NSIS 安装器升级到正常用户安装目录，退出并再次启动后原生图库可正常读取。安装程序中的主程序与便携程序的差异仅为 Tauri 的三字节 NSIS 包类型标记；规范化该标记后其余字节一致。这个差异由[该版本 bundler 源码](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.2/crates/tauri-bundler/src/bundle.rs#L35)解释，不代表不同业务源码，也不将不同产物的原始摘要宣称为相同。

实际 NEF 经共享 Rust 服务生成 t256 的 171×256 JPEG（31,707 字节）和 p2560 的 1707×2560 JPEG（2,174,654 字节）。真实原生窗口显示带 NEF 标签的影像且无载入错误；关于/更新页显示 0.2.1 为最新版本。此处证明该真实样本及对应流程，不外推全部相机 RAW 变体。旧私有副本中的 NEF 请求曾在解码前遇到 `E_RANGE_HTTP`/404，缓存 JPEG 则可显示；这不是 NEF 解码失败证据。

## 更正早先的数据来源判断

早先 schema5、4 个图库、7,380 条资产的样本来自 MSIX AppData 重定向中的旧 0.1.0 私有副本，并非物理用户的日常 preview.9 数据。早先的迁移探针结果仍成立，但“真实日常库”“旧日常安装未变”等由该私有视图作出的判断不能作为物理安装状态证据，以本记录的交叉核对结果为准。

本次对 UNC 物理路径视图、未受该重定向影响的 WMI 系统进程观察及实际应用进程作交叉核对，没有提权或修改系统设置。MSIX 对 AppData 的私有存储和合并视图行为见 [Microsoft 说明](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes#appdata-operations-on-windows-10-version-1903-and-later)。以后从打包工具验收时，不再仅用普通路径的 `Get-Item` 或一次复制判断用户数据与安装版本。
